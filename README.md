# Эмулятор командной строки UNIX

## Общее описание

Графический (GUI) эмулятор командной строки UNIX-подобной ОС,
разработанный в рамках практической работы по дисциплине
«Конфигурационное управление» (Вариант №19).

Написан на Go, интерфейс построен на библиотеке
[Fyne](https://fyne.io).

## Сборка и запуск

Требуется Go 1.27+ и компилятор C (для Fyne).

```bash
make build   # собрать в bin/emulator
make run     # запустить
make test    # запустить тесты
make lint    # проверить стиль кода (нужен golangci-lint)
make clean   # удалить bin/
```

При каждом pull request и push в `main` GitHub Actions проверяет сборку,
тесты, форматирование, стиль кода по правилам курса (`.golangci.yml`:
функции до 40 строк, цикломатическая сложность до 10, Godoc и др.)
и формат сообщений коммитов (Conventional Commits).

Структура проекта:

```
src/main.go      точка входа
src/shell/       парсер, команды, сессия
src/ui/          графический интерфейс (Fyne)
src/config/      параметры командной строки и INI-файл
src/logger/      журнал команд в CSV
tests/           тесты
scripts/         стартовые скрипты и тестовые скрипты ОС
configs/         примеры INI-файлов
Makefile         сборка, запуск, тесты, линтер
```

## Этап 1. REPL

- Окно с полем вывода и строкой ввода команд.
- Заголовок окна формируется из реальных данных ОС:
  `Эмулятор - [username@hostname]`.
- Парсер разделяет ввод на команду и аргументы по пробелам.
- Сообщения об ошибках: неизвестная команда, неверные аргументы.

| Команда       | Описание                                           | Пример        |
|---------------|----------------------------------------------------|---------------|
| `ls [арг...]` | Заглушка: выводит имя и аргументы                  | `ls -l /home` |
| `cd [путь]`   | Заглушка: выводит имя и аргумент (не более одного) | `cd /tmp`     |
| `exit`        | Закрывает эмулятор (аргументы запрещены)           | `exit`        |

Пример:

```
$ ls -l /home
ls -l /home
$ cd a b
error: invalid arguments: cd: too many arguments
$ foo
error: unknown command: foo
$ exit
```

## Этап 2. Конфигурация

### Параметры командной строки

| Параметр          | Описание                              | Пример                         |
|-------------------|---------------------------------------|--------------------------------|
| `--vfs <путь>`    | Путь к директории VFS                 | `--vfs vfs/files`              |
| `--log <путь>`    | Путь к лог-файлу (CSV)                | `--log emulator_log.csv`       |
| `--script <путь>` | Путь к стартовому скрипту             | `--script scripts/stage2.txt`  |
| `--config <путь>` | Путь к конфигурационному файлу (INI)  | `--config configs/emulator.ini`|

При запуске в окно выводятся все параметры в формате `ключ=значение`.
Всё, что выводится в окне, дублируется в консоль, из которой запущен эмулятор.

### Конфигурационный файл (INI)

```ini
; комментарий
[emulator]
vfs = vfs/files
log = emulator_log.csv
script = scripts/stage2.txt
```

Значения из командной строки имеют приоритет над значениями из файла.
Неверная строка или неизвестный ключ — ошибка, эмулятор завершается с кодом 2.

### Лог (CSV)

Каждый вызов команды записывается строкой
`time,user,command,args,error`; поле `error` содержит сообщение
об ошибке. Все поля всегда заполнены: пустое значение (нет аргументов,
нет ошибки) записывается как `-`.

```
time,user,command,args,error
2026-10-03T18:50:51+03:00,anastasia,ls,-l /home,-
2026-10-03T18:50:51+03:00,anastasia,foo,-,unknown command: foo
```

### Стартовый скрипт

Команды выполняются по очереди, ввод и вывод показываются в окне,
как будто их набирает пользователь. Строки с ошибкой сообщаются
(с номером строки) и пропускаются. Пустые строки и строки,
начинающиеся с `#`, игнорируются. Команда `exit` в скрипте закрывает окно.

### Тестовые скрипты ОС

```bash
scripts/test_args.sh     # все параметры командной строки по очереди
scripts/test_config.sh   # INI-файл, приоритет флагов, ошибки конфигурации
```
